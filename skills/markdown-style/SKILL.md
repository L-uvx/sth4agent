# Markdown 编写规则

适用于项目内所有 Markdown 内容，按以下格式书写：

## 文章开头引文

- 文章标题下方的引文说明（定位、背景、核心结论等），使用 `*` 无序列表格式，不使用 `>` 引用块
- 每条引文以 `* **标签：** 内容` 的格式书写
- 示例：
  - ✅ `* **定位：** 这是一份 xxx 文档`
  - ✅ `* **核心结论：** xxx`
  - ❌ `> **定位：** 这是一份 xxx 文档`

## 标题层级

- 二级标题使用：`## 一、标题`、`## 二、标题`、`## 三、标题`
- 三级标题使用：`### 1、标题`、`### 2、标题`、`### 3、标题`
- 四级标题使用：`#### a. 标题`、`#### b. 标题`、`#### c. 标题`

## 列表层级

- 普通有序列表使用：`1.`、`2.`、`3.`
- 在"分组说明"场景中，使用以下结构：
  - 分组标题使用 `*` 开头（不用 `-`）：`* 角色任务：`、`* 项目内可深挖：`
  - 分组标题与数字列表之间**必须空一行**
  - 数字列表**不缩进**，顶格书写
  - ✅ 正确格式：
  ```
  * 项目内可深挖：

  1. 第一条内容
  2. 第二条内容
  3. 第三条内容
  ```
  - ❌ 错误格式（连写 + 缩进 + 用 `-`）：
  ```
  - 项目内可深挖：
    1. 第一条内容
    2. 第二条内容
  ```

## 编号起始规则

- 二级标题编号必须从 `一` 开始，禁止使用 `零`、`负一` 等非常规起始编号
- 如果需要在正文最前面增加章节，应将所有现有章节顺延重新编号，而不是用 `零、` 作为前置章节

## 标题简洁规则

- 标题中不重复已由层级结构表达的信息，直接写主题内容
- 禁止在三级标题中重复二级标题已有的分组前缀，例如：
  - ❌ `### 1、模块 A：认知与方法论` → 「模块 A：」是赘述，二级标题已表明这是场景总览下的分组
  - ✅ `### 1、认知与方法论`
- 禁止在三级标题中添加与编号无关的序号前缀，例如：
  - ❌ `### 1、场景 1：CSS 布局与响应式` → 「场景 1：」与 `1、` 重复
  - ✅ `### 1、CSS 布局与响应式`

## 分段规则

- 段落与章节之间不使用 `---` 分割线
- 统一使用空行分段

## 收尾句标点

以下类型的独立收尾句**不加句号**（`。`）：

1. **原则/要点行**：以 `**关键原则：**`、`**操作要点：**` 等加粗标签开头的单行总结
2. **代码块后提示句**：紧跟代码块（` ``` `）之后的独立说明或结论句
3. **来源标注行**：以 `**来源：**` 开头的单行标注

示例：

- ✅ `**关键原则：** 日志必须带模块前缀和关键 ID`
- ✅ `把 curl 的完整输出复制给 AI，比描述「接口报错了」有效 100 倍`
- ✅ `**来源：** Go 官方 Testing/Debugging 指南、项目开发调试实践`
- ❌ `**关键原则：** 日志必须带模块前缀和关键 ID。`
- ❌ `把 curl 的完整输出复制给 AI，比描述「接口报错了」有效 100 倍。`

## 示例

```md
## 一、二级标题
### 1、三级标题
### 2、三级标题
#### a. 四级标题
#### b. 四级标题
### 3、三级标题
```
